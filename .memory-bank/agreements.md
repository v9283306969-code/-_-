> Формат: номер, дата, решение, почему. Новые решения добавлять в конец. Устаревшее — в «Архив» внизу файла, не удалять.

## AGR-001 (2026-05..09) Старая схема разметки
Банковские поступления маркетплейсов = «Неналоговая база»; доходы и расходы вносятся по первичным документам. Двусторонний Ozon «Выкуп товара у селлера» — техническая запись, не считается. Декомпенсация = «Возврат прихода».
Почему: до октября 2026 не было официальных рекомендаций по взаимозачёту для АУСН.

## AGR-002 (2026-10-27) Переход на официальную схему «взаимозачёт»
С октября 2026: поступления от маркетплейсов = «Приход»; удержания маркетплейсов = «Взаимозачёт» (Приход + Расход) — Ozon: акт, перевыставление, «Звёздные», УПД-1, страховка; WB: строки 2.1–3 и 6–7 недельного отчёта. Займы: Приход = долг + проценты, Расход = только проценты. Возвраты: Приход + «Возврат прихода». Уведомления о выкупе WB не вносятся (только удержания из «По выкупам»). Месяц операции = дата в отчёте маркетплейса. Переходные поступления (Ozon saldo 776 178,03 на 30.09; WB недели по 30.09) = «Неналоговая база».
Почему: официальные рекомендации ФНС и Ozon Bank от октября 2026.

## AGR-003 Месяц отнесения WB
Еженедельный отчёт WB → месяц даты в шапке отчёта (воскресенье; с 31.08 WB делит недели по границе месяца). Уведомление о выкупе → месяц его НЕДЕЛЬНОГО отчёта (дата «от» — понедельник), а не собственная дата.
Почему: уведомление финансово входит в свою неделю; вывод подтверждён сверкой с документами.

## AGR-004 Первичные документы важнее API
При расхождениях цифр API WB/Ozon с подписанными PDF первичкой верна таблица Виталия (кейсы: баллы лояльности, «Итого» выкупа). API-расхождения помечались ошибками ошибочно — пометки сняты и удалены по требованию владельца.
Почему: PDF/УПД — юридически значимые документы; API-выгрузки могут отличаться составом.

## AGR-005 Единый банк
Все операции ведутся через Сбер (счёт ••••0486). ОЗОН Банк и Кубань Кредит — без движений (подтверждено владельцем).
Почему: упрощение сверки и разметки; подтверждено отсутствием оборотов.
